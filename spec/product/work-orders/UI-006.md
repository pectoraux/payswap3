# UI-006 — Activity, State, Waiting, Exception, and Recovery UX

**Status:** BLOCKED  
**Depends on:** UI-003, UI-004, UI-005

## Objective
Make the system legible after a task leaves the happy path: what happened, what is happening, what is known, what is unknown, and what happens next.

## Acceptance
- Activity is organized around user-meaningful events rather than protocol logs.
- Waiting states explain what is awaited and whether user action is required.
- UNKNOWN is never presented as failure.
- Needs-attention states expose a recovery path where one exists.
- Recovery flow communicates observed facts before proposing action.
- Notifications are task/outcome/exception/evidence oriented, not telemetry spam.
- State-language tests and recovery dogfood pass.

# Architecture Change Requests

Frozen v0.1 architecture may change only through an Architecture Change Request (ACR).

An ACR must:

1. identify the exact frozen rule or boundary being changed;
2. explain why the current architecture is insufficient;
3. define the proposed new immutable architecture version;
4. identify affected objects, commands, events, invariants and work-order contracts;
5. define migration/compatibility implications;
6. define required simulation, replay, shadow, conformance and dogfooding evidence;
7. be approved by the Architect before implementation scope changes.
